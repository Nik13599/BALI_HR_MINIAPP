# BALI HR Mini App

В репозитории сохраняются два изолированных режима:

- браузерная демонстрация — существующий `site/index.html`, локальные тестовые данные и `localStorage`;
- production-приложение — серверный Telegram-вход, PostgreSQL, закрытые клановые чаты и отдельная админ-сессия.

Демо не является источником production-авторизации или production-данных.

## Кланы внутри BALI People

Клановая часть встроена в текущее приложение:

- в `site/index.html` она открывается в существующем BALI PEOPLE через переключатель `Люди / Мой клан`;
- в `site/admin-beta4.html` управление находится в общей навигации в разделе `Кланы BALI PEOPLE`;
- отдельные пользовательские и административные beta-страницы не используются.

Браузерное демо использует внутренний адаптер `site/bali-clans-demo-core-beta4.js`, связанный с активным пользователем BALI. Изменения чата и админки синхронизируются между вкладками. Вне demo-режима тот же интерфейс обращается к защищённым `/api/v1/*`: сервер проверяет Telegram-сессию, членство, роль и разрешения на каждую операцию.

## Production-маршруты

- `/app` — пользовательское Telegram Mini App;
- `/admin` — отдельная защищённая админ-панель;
- `/demo` — браузерное демо, доступно только в `demo` и `development`;
- `/api/v1/health` — проверка состояния процесса.

В `staging` и `production` маршрут `/demo` отключён. При открытии `/app` вне Telegram отображается только экран перехода в официального бота.

## Локальный запуск

Требуются Node.js 22+ и PostgreSQL с уже применённой базовой схемой BALI, включая таблицу `public.events`.

```bash
cp .env.example .env
npm ci
npm run migrate
npm run dev
```

Для первого администратора заполните `ADMIN_BOOTSTRAP_EMAIL` и `ADMIN_BOOTSTRAP_PASSWORD`. Учётная запись создаётся один раз; после этого bootstrap-пароль следует удалить из окружения и перезапустить сервис.

Production-конфигурация требует:

- `BALI_ENV=production`;
- `DATABASE_URL`;
- `TELEGRAM_BOT_TOKEN`;
- `TELEGRAM_BOT_URL`;
- случайный `SESSION_SECRET` длиной не менее 32 символов;
- HTTPS и `TRUST_PROXY=1`, если TLS завершается на доверенном reverse proxy.

## Telegram-вход

Клиент отправляет серверу исходный `Telegram.WebApp.initData`. Сервер проверяет HMAC-подпись и возраст `auth_date`, берёт Telegram ID только из подписанных данных, связывает его с внутренним пользователем и создаёт случайную серверную сессию. В cookie хранится только непрозрачный токен; в базе — его хеш.

Пользовательская и административная сессии используют разные HttpOnly-cookie. Telegram-сессия не даёт доступ к `/api/v1/admin/*`, а админ-сессия не заменяет пользовательскую.

## Права кланового чата

Все операции повторно проверяются сервером. Активный участник получает только базовые права чтения, записи, ответов, голосования и жалоб. Главный клана получает управленческие права по умолчанию. Роли заместителя, модератора и рекрутера сами по себе дополнительных прав не дают.

Администратор может выдать или запретить ровно один permission-код, задать срок действия и отозвать grant. Явный `deny` имеет приоритет, включая ограничения главного клана. Выход или исключение из клана немедленно закрывает историю чата.

## Миграции и откат

`npm run migrate` применяет `*.up.sql` по имени в одной транзакции с записью checksum. Изменять уже применённый файл нельзя — для следующего изменения создаётся новая миграция.

Для контролируемого ручного отката предусмотрен:

```text
migrations/001_telegram_auth_clan_chat.down.sql
```

Перед откатом production-базы обязателен backup. Down-миграция удаляет данные клановых чатов и сессий.

## Проверки

```bash
npm run check
```

Команда запускает линтер, typecheck, 64 серверных security/integration-теста, 9 smoke-тестов demo/beta и production build. CI также выполняет аудит production-зависимостей.
